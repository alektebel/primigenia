# M0, the Godot foundation (G76)

Branch `godot-m0`. Plan: `docs/godot/PLAN-m0.md`. Run: `make godot && godot --path godot`.

## What exists

* GDExtension `cpore` (C++ glue only, simulation stays in `build/libcpore.a`): `CporeTerrain`, `CporeWorld`.
* Island from the C terrain generator (W20 defaults, seed 1), cached on disk, loading screen on first run.
* Chunked GPU-displaced terrain with 5 LODs and skirts, palette C land shading, sea and lakes, wind grass,
  sky and aerial perspective calibrated to the hero's three.js pipeline.
* The 10 Hz C world bridge with interpolation and replayable logs, chase camera (G72 numbers), click/WASD controls.
* A placeholder creature standing in for g-creature; the real module, locomotion, UI and studio hook in by path.

## Interfaces

### `CporeTerrain` (RefCounted)

`version()`, `defaults()` (46 params, ints as int), `validate(params)` (0 or `CP_TERR_ERR_*`; ints accept integral floats,
floats must be finite, unknown keys rejected), `generate(params)` -> `{error, version, seed, n, size_m, params, hash, height,
flow, sediment, water_level, material, caves, volcano}` (synchronous, run it on a Thread; a concurrent second call on the same
instance returns `CP_TERR_ERR_BUFFER`), `progress()` -> `{stage 0..4, done, total, running}` (lock-free), static `hash(data)`
(recomputes the C hash over a dictionary), static `surface_maps(data)` (presentation maps, see below).
Caves are in Godot axes (`position = (x, y_alt, z)`), `volcano` is `Vector4(x_m, y_m, radius, crater)` in map axes.

### `CporeWorld` (RefCounted)

`version()`, `default_setup(seed)`, `default_profile()`, `species()`, `reset(setup)` (0 or -1, a failed reset keeps the previous
world), `get_setup()`, `step(input)` (returns the hash, `""` and no step if the input is malformed or `hx/hz` do not fit int16),
`command(text)`, `order(input)`, `order_error(code)`, `state()`, `observe()` (256 KiB buffer), `hash()`, `height/ground/can_walk`.
Setup schema `{seed, terrain_seed, terrain, nest: Vector2, flat_height, water: Vector3(x, z, r), player: Profile, wild: [...],
obstacles: [...]}`; state schema in PLAN-m0.md 3.3 (`entities`, `combat.fighters`, `combat.events`, `order`, `accepted`, `arena`...).
Proof of determinism: the three committed golden logs replay tick for tick through `CporeWorld` and a Godot session log replays
identically in `build/world_cli --replay`.

### `Game` autoload (`game/game.gd`)

Signals `island_ready`, `world_ticked(state)`, `combat_events(events)`, `creature_clicked(id, world_pos)`; vars `settings`
(`seed`, `grass`, `quality`, `wild`; `[game]` in `user://settings.cfg`), `terrain`, `data` (TerrainData), `stage`, `camera`,
`modal_open`; `ground(x, z)`, `movement_blocked()`, `player_genome()` (`--genome=`, newest `user://studio/*.json`, bundled Merodeador),
`goto_island()`, `goto_studio()`, `set_island(entry)`.
`user://` is `~/.local/share/primigenia/` (`config/use_custom_user_dir`).

### Terrain data and cache

`TerrainData.ground(x, z)` is the exact LOD0 mesh surface (same triangle diagonal as the shaders); `normal`, `is_pond`, `is_sea`.
Derived maps (`CporeTerrain.surface_maps`, C++ because it is a plain 1M-cell loop, 17 ms; not measured in GDScript): RGBA8
`surface` = R material id, G grass mask, B cavity, A wetness; `chunk_bounds` min/max per 64-cell chunk.
Cache key `island-<seed>-t<generator>-r<render prep>-<sha256 of canonical params>.bin`; zstd; magic + format + one Variant
(no objects); a hit also requires the recomputed C hash to match.

### Stage bridge (`game/stage/`)

`StageWorld` (Node): own accumulator at 0.1 s (`min(delta, .25)`), `ticked`/`combat_events` signals, `sample(id, alpha)` ->
`{pos, yaw, speed, vel}`, `export_log()` (`CPORE_WORLD_LOG 1`, floats written as the shortest text that round-trips float32).
`stage_setup.gd` builds the C setup for the island, `profile.gd` ports `web/engine/profile.js` (fixtures generated by
`game/tests/fixtures/gen_profile_expected.mjs` from the JS), `world_log.gd` parses and writes the log format.

## Look pipeline findings

* The Compatibility renderer applies its own `srgb_to_linear` polynomial to what a shader writes to `ALBEDO` (a StandardMaterial
  unshaded colour 0.5 and a shader `ALBEDO = 0.5` both read back 128). `godot_albedo()` in `look.gdshaderinc` inverts that
  polynomial (4 Newton steps), so shaders can hand the tone mapper a true linear colour. Values above 1 are allowed.
* Godot's ACES is three.js ACESFilmic with exposure bias 1.8 and a white divisor. `tonemap_exposure = 0.926` (= (1/0.6)/1.8)
  and `tonemap_white = 15.4` (where the fit curve reaches 1.0, derived by hand) match three within 2.36/255 on 32 patches
  (`calibration.json`; the best candidate came out equal across whites 12..20).
* Not every display colour is reachable: the hero's tone mapper desaturates bright colours, so (0.25, 1, 0) can never occur.
  The plan's 5x5x5 round-trip gate therefore runs over the reachable subset (58 colours incl. the palette's own sky/haze
  colours); worst error 0.70/255. 72 grid colours were skipped.
* Chosen route: the calibrated one (not the linear fallback). Creature materials lit by Godot get ACES at exposure 0.926;
  g-creature tuned for 1.4 and will need a retune at integration.
* `get_image()` of the root viewport returns what the screen shows; evidence uses it under xvfb + llvmpipe only.

## Verified

`make godot-test`: 300 checks, 0 failures (terrain hashes equal `build/terrain_cli` for (42,64), (7,128), (1234,128), (1,1024);
validation; threaded progress and concurrency guard; the three golden world logs replay all 3000 ticks each; the Godot session
replays in `world_cli`; cache miss/hit and five corruption paths; ground() exactness; LOD thresholds and mesh sizes; grass
reproducibility; profile fixtures against the JS; input; camera; actors). `make godot-render-test`: tone-map gate 2.36/255,
round trip 0.70/255, sky horizon 0.5/255, sun symmetric, contact shadow (0.122 shaded vs 0.325 lit), land not water, 0 sky pixels
through LOD4 terrain. Timings (`docs/evidence/godot/m0/timings.json`): generate + store 3.6 s on a worker thread, cache hit 37 ms,
island scene build 0.95 s under software GL.
The cache tests print engine `ERROR` lines while reading deliberately corrupted files; they are expected.

## Not verified / known gaps

* **C world gap (kept on purpose):** the C world uses analytic or flat heights and a hard +-195 m bound, so M0 runs it FLAT at the
  valley floor height 42 m. Island heights are visual only; creatures are drawn at `Game.ground(x, z)`; the playable area is the
  +-195 m valley. BACKLOG item 6 (a C heightfield source) is a core change and not in M0. There is no invisible wall yet beyond
  C's own clamp.
* One water circle for the C world: the largest connected pond inside the square (the plan's "all ponds" circle covered the nest).
* The g-loco path in `actor_driver.gd` and the real g-creature path are untested here (modules absent). The fake-module test proves
  only the hook.
* Fight camera framing is unit-tested; a live fight was not exercised (the evidence runs with `wild = false`).
* No trees, rocks, flowers, clouds (hero extras); no curated pre-baked seed (W13: a 5 MB binary is an owner decision).
* Linux only. `template_release` and Windows/macOS libraries are not built.
* Cache has no eviction (one ~8.7 MB file per seed/version; plan assumed ~5 MB).
* Evidence uses 60000 blades (software GL); the game default is 252000.
