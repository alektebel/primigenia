## Godot migration rules (G76)
- Engine: Godot 4.7.2 at `godot` (~/.local/bin/godot). GDScript for game code. Desktop only.
- The repo is being migrated in parallel by several agents, each owning ONE folder under godot/. Only create or edit files inside your own folder (plus your own docs file and evidence folder named in your task). If godot/project.godot does not exist on your branch, create a minimal one for your tests; the final one comes from the M0 foundation branch, so keep any settings you need listed in your README instead of relying on project.godot.
- Another agent (Codex, branch godot-m0) builds the foundation: the GDExtension over the C core (godot/extension/), the island terrain from the C generator with on-disk cache, the Spore-style chase camera and the click/WASD controls. Do not duplicate it; define clean interfaces (documented in your README) that the integration will connect.
- Source of truth for behaviour and look: the existing web implementation (web/studio, web/creature/rig.js, web/stage, tools/hero/build_hero.py) and docs/DESIGN.md. Port behaviour faithfully, improving only where the task says so.
- Tests: headless GDScript tests runnable with `godot --headless --path godot --script <test>` (or a test scene), plus a Makefile target named in your task. Images: `xvfb-run -a` with `LIBGL_ALWAYS_SOFTWARE=1` and `--rendering-driver opengl3` (software only; never the GPU, never windows on the user's desktop). Keep renders few (the laptop fans matter), always `nice -n 10`.
- Never modify art/reference/, core/ algorithms, or other agents' folders. No pushes. No installs beyond what your task allows. Commit in small clear commits as you go (end each message with your Co-Authored-By line). Report honestly what is done, what is verified and what is not.
- Godot pitfall (fans!): a `godot --script` that fails to compile never quits and can sit at ~900% CPU under xvfb. ALWAYS wrap Godot runs in `timeout` (e.g. timeout 300) and check scripts first with `godot --headless --check-only --script <file>`.
